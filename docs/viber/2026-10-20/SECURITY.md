## Visitor checklist

- Artifact: no compilation step; actual local HTML/JS routes were exercised. An immutable Git release of the entire feature set has not been prepared.
- Public DB: the new SQL platform has no browser-facing database endpoint or anon key. Legacy Supabase configuration is conditional; live policies were not queried.
- Response minimization: anonymous protected endpoints expose error codes only; public catalog exposes fixed plans. Private room previews and member attendance scope are tested. No real personal data sampled.
- Source maps: `/js/platform.js.map` returns 404 locally; no app-generated browser bundle/source map exists. Vendor dependency maps are not a secret-control boundary.
- Leftover doors: local `.env`, `.git/HEAD`, server source, data, docs and debug probes return 404; root returns 200 as positive control. Live `.env`, `.git/HEAD`, debug and random route return 404.
- Errors: malformed account/platform inputs return bounded 400/403/404 responses, not SQL errors or stack traces.
- Private indexing: workspace HTML has noindex and no embedded personal payload. Production workspace routes are absent, so deployed private-page metadata cannot be verified.
- Analytics: no Clarity/Hotjar/GA/PostHog/LogRocket initialization found in the inspected core pages/scripts. No vendor dashboard setting was asserted.
- Public repository: GitHub metadata confirms `alkhunizan/Co-study` is public. History-wide credential absence is not proven.
- Public contact email in marketing is intentional; no personal user content was collected.

An unauthenticated process-crash condition was confirmed locally (V9-01). No live exploitation or live secret exposure was tested or established. Release parity, unresolved user-facing failures and external operating evidence remain additional gates.
