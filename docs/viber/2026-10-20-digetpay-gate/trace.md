## Findings and phase-4 probes

1. **P2 candidate, sandbox availability/provider-call amplification: unsigned transaction-mode notification backlog is unbounded per order.** digetpay-billing.js:143–153 keys outbox by `(orderId, transactionId)` in transaction lookup mode; arbitrary distinct UUIDs for a known order create distinct durable rows. routes.js:31–36 applies 120/min per IP, but there is no order/global queue bound. drain:157–179 permits up to 20 provider lookups per candidate. An account owner already knows their order ID; attacker does not need another user's secret. Session mode coalesces and production payment mode is disabled, so do not classify as live theft. Probe locally with fake provider: three distinct valid UUID hints, compare row count/provider calls, repeat same hint positive-control coalescing, verify no entitlement granted.
2. **P2 candidate, late checkout transition conflict:** digetpay-billing.js:112–117 sets old approved order to review when an active subscription exists; migration 002:18–19 permits only one creating/pending/unknown/review per user. Investigate whether reachable sequence can retain a newer open order alongside an active subscription, then approve older expired order. Do not count until concrete legal-state reproduction; ordinary checkout refuses a new order when subscription active.
3. **Deployment dependency, not code exploit:** production recovery has no delivery implementation and DigetPay is sandbox-only. docs/payments/2026-10-20-digetpay/IMPLEMENTATION.md:46–52 makes session/transaction status binding conditional on actual merchant evidence. Enabling production requires separate implementation/acceptance, not env toggle.

Next mandatory probes: anonymous every protected endpoint; signed-in A vs B focus/cohort/payment reads+writes; cross-account cache with sequential sessions; phone empty/object/overlong; checkout double click/provider timeout/reload; fabricated success return and webhook with fake transaction; failed transaction then successful retry with different ID; duplicate verify/no second grant; refund then stale approved; malformed socket/null + positive control; denied video before provider call; role/MFA expiry; recovery expired/used token; persistence failures without false UI success.
