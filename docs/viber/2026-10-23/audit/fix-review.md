## Remaining candidate: account provider-configuration failure has no recovery UI

**Source-supported; not a verified finding and no severity assigned.** `account.html:216-227` initially hides the only Google sign-in action. At `:458-465` its runtime-config fetch still has neither a deadline nor retry; a rejection is silently swallowed and an indefinitely pending request leaves the provider hidden. This is a sibling of the other raw runtime fetches changed by this patch. Google-only accounts cannot use a known password as a substitute: `services/auth/google-routes.js:213-223` generates a random internal password and marks the provider as Google.

Bounded local probe: stub runtime-config with `googleAuthEnabled: true` as the success control; fail or hold that request on a fresh `/account` load; record whether a provider-loading failure/retry action is available; restore the endpoint and exercise recovery without losing typed form values. Do not follow the OAuth link or contact Google. If reproduced and accepted, use a bounded runtime request plus a localized inline Retry action for configuration failure; retain hidden Google UI when a successful configuration says it is disabled. A timeout alone settles the fetch but does not restore the missing action.

This candidate was sent to the main agent while the review was in progress. It is not counted as an open verified defect or as a tested boundary in this report.
