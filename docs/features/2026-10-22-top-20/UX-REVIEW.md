# Journey and visual review

The selected additions form one loop: choose a small next step, use a repeatable rhythm, focus, reflect and return to a familiar room or appointment. Study, Progress, Circles and Account remain the four primary destinations. Planning is a secondary destination, with task details collapsed for a quick start.

The real-browser review uses synthetic local accounts, real persisted tasks/circles and honest credited time. The short visual fixture earns zero completed minutes; the charts deliberately show zero instead of manufactured activity. A group and its member count are actual fixture records, and resource/room names identify local review examples.

| Journey | Observed result |
|---|---|
| Plan → focus → reflect → find the session | A private project/task/checklist leads into an explicitly linked session. Completed time comes from the ledger. The reflection is retrieved through journal search. |
| Interrupted task save | A response aborted after commit preserves the form and reuses the request key. The retry returns the saved task once. |
| Routine across surfaces | Ordinary and guide controls agree. A second tab can pause; returning preserves the pause. A stopped old guide leaves a newer server session untouched. |
| Return after another surface pauses a closed routine | Remaining guidance stops at the authoritative pause timestamp rather than consuming the closed interval. The new regression proves the pre-fix failure. |
| Circle appointment → saved room → resource shelf | Membership is checked for every read/write and before reminder delivery. Removal hides unavailable room metadata and removes agenda/calendar/resource access. |
| Draft → language change / reordered request / shared-cookie account switch | Main forms stay mounted, resource drafts remain within the same circle/owner, late journal data cannot replace a newer search, and stale account requests are rejected before data access. |

Actual-font screenshots cover Tasks, Routines, Saved places, My agenda, Insights/journal, guided Progress, circle resources and Study. Representative widths are 320, 390, 768 and 1440 pixels in Arabic/English and light/dark modes. The evidence records actual document attributes, loaded font families, overflow and accessibility results. The additional enlarged-text pass doubles each text/control font at 390 pixels and checks the primary action is inside the viewport and unobstructed.

Visual corrections made after browser inspection: restored numeric form defaults, reduced the task form to a title plus optional details, used global visible feedback/reminders, retained the warm paper/night-sky palette and real Tajawal/Amiri/Inter/Newsreader typography, and matched the brand link's accessible name to its visible content. The screenshot gallery identifies before captures made with blocked web fonts and after captures with loaded fonts; typography differences alone are not attributed to code changes.

Activation can be defined as a first completed session with positive server credit. A return can be another credited session on a later Riyadh day. These are definitions for evaluation, not measured adoption or retention gains. No new third-party analytics or private-content telemetry was added; optional existing device counters retain their consent boundary.

Real hardware/provider acceptance and production field performance remain outside this local run. There is no claim of a live deployment, guaranteed closed-browser reminders, universal browser/device perfection, or a measured retention uplift.
