# Verification execution notes

All data and accounts used in this refinement are synthetic. The app runtime is outside the network checkout, while deliverable reports/logs/screenshots/helpers are inside this folder. Source and regression tests stay in their established app locations.

## Runtime containment and corrections

- Git's mapped UNC ownership check was resolved with command-scoped safe.directory; no global trust setting changed. Git path quoting was disabled for source enumeration so Arabic filenames were not mistaken for escaped paths.
- The host defaults to Node 24. Verification explicitly selects the cached Node 22.23.3 executable. The initial install used npm's host shim; it was superseded by a fresh successful Node 22 `npm ci` and a per-process Node 22 npm shim for nested scripts. No dependency versions were changed.
- The first runtime copier omitted the ambient `.d.ts` and `.gitignore`. Resulting compiler/lint configuration errors were isolation defects, not app findings. The copier includes both now. An accidentally copied top-level copy module was removed only from the disposable runtime. Current parity verification must reject unexpected author-code files.
- A shared npm shim initially caused a helper file race when independent checks ran together. Helpers now use per-process directories. These failed execution attempts are retained; they are superseded by successful commands in the ledger.
- Terminating the first disposable preview left the deliberate PGlite single-runtime lock. Before recovery, its recorded PID was checked and found absent; the exact stale lock was archived in `evidence/stale-preview-lock.json`. The following startup restored two previously created synthetic accounts. No active lock or production data was removed. This demonstrates the operational requirement to inspect stale locks, not automatic lock deletion.

## Test corrections and discovered app defects

- The first lobby retry fixture blocked Socket.IO's JavaScript as well as its transport, so it never reached a real connection failure. It now blocks only EIO transport requests. The retry assertion stayed intact.
- The account provider-link test originally assumed a missing Google subject was `undefined`; the account constructor uses `null`. It now compares the exact original subject. A stale linking attempt still must leave it unchanged.
- The circle lifecycle fixture previously omitted the live user map, which the new identity boundary requires. Supplying its owner/member map restores the intended valid request. Its assertions that private scope and receiver revocation survive failed persistence remain unchanged.
- The initial extended sweep navigated each room twice per state and eventually reached the real join rate limit. The helper now sets preferences before one navigation per state. Production limits were not loosened. Rate-limit/error contrast findings were still repaired.
- Rendered screenshot review found an empty shared-goal grid overriding hidden. Explicit hidden semantics were restored and a regression assertion added. The 200% text review also found real entry/header overflow. Keyboard testing found native skip-link focus stolen by the hash router. These were application defects, not waived checks.
- The broader candidate gate found duplicate `data-view` hooks on new Home content links, breaking existing strict navigation selectors, and the room Start action four pixels below a 900px desktop viewport. Content links retain their native URLs without navigation-only hooks; primary timer controls now precede secondary duration settings in DOM and visual order. The three unchanged legacy journeys passed after correction. The superseded `delivery-ci` process was stopped explicitly; its partial log is not final evidence.
- Browser artifacts now buffer on the local disk before copying into this folder, avoiding network-share write contention. Videos, screenshots and assertions remain enabled. No timeout or assertion was weakened to obtain the final result.
- The first final SEO invocation omitted the script's required base URL and returned its usage error. `verified-seo-local` supplies the loopback preview URL and is the applicable successful verification.
- Git had no configured author identity. Local checkpoints use command-scoped `Codex <codex@localhost>`; no global or repository identity setting was changed, and no user identity was impersonated.
- Screenshot inspection caught a new matrix-helper error after the first complete green gate: changing localStorage before hash-only navigation did not change the live document language/theme. The app controls worked. The regression now uses actual language/theme controls and asserts the rendered attributes before every capture; the complete gate is repeated on that stronger source. Supplementary helpers force full document navigation and assert actual state. English canonical landing views use `/en`.
- Axe's CSSOM preloader attempts XHR to Google stylesheet URLs, which the app correctly disallows under `connect-src`. A focused diagnostic recorded its resource type, phase and URL; normal stylesheet and font loads succeeded. These tool requests remain explicit in `online-visual.json`, separate from real app/font failures. A font canceled during deliberate navigation is likewise recorded by phase; errors while rendering, font-face errors, layout failures and serious/critical axe findings still fail. The existing standalone online-font test has no axe injection and passed with no font/CSP diagnostics.
- PowerShell 5 `Copy-Item` failed on long Playwright artifact paths. `robocopy /E` backfilled them without deletion; extended-path SHA-256 comparison verified all 134 original files. The launcher now uses long-path-safe copying. No test result was changed by artifact recovery.
